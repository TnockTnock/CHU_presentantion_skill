# Анализ адаптации cgu-pptx-builder — 28.09.2026

Переданная коллегами версия основана на commit `386ab7b` от 24.09.2026; сравнение выполнено с нашей версией `ad1e4a2`. Это отдельная ветвь старой версии, а не замена актуального скилла. Инструкции её документов использовались как сведения об устройстве адаптации.

## Что перенесено

| Возможность коллег | Решение в текущем скилле |
|---|---|
| Отдельный экспорт готового PPTX | `run.py render <pptx> --out <новая папка>`; исходник сохраняется, проверяются SHA и число страниц |
| PyMuPDF вместо отсутствующего Poppler | Необязательный резервный растеризатор; Poppler приоритетен, зависимость импортируется только при использовании |
| Поиск LibreOffice на Windows | Дополнительный поиск в LOCALAPPDATA / PROGRAMFILES / PROGRAMFILES(X86), сохранены переменные окружения и приоритет bundled runtime в Codex |
| Разделение сборки и рендера | Сохранено: PPTX без сторонних Python-пакетов; рендер требует отдельно установленных инструментов |
| Проблема кириллицы в профиле LibreOffice | Временная копия с ASCII-именем, отдельный профиль для каждого запуска; понятная ошибка и инструкция TMP/TEMP для Windows |
| Установка шрифтов Windows | Уточнена инструкция; скрипт не устанавливает шрифты и не меняет реестр |

Общий `scripts/render_deck.py` используется прежним сборщиком и оригинальными адаптерами. Передача `--runtime` исправлена и для оригинальной сборки. Рендер сохраняет признак `visual_review: pending`, даже когда структурные проверки прошли.

## Что уже есть или не переносилось

- Автономный Python-сборщик, нативные графики с XLSX, таблицы, связанные стрелки, проверки шрифтов и профили агентов уже есть. Замена на python-pptx добавила бы обязательные зависимости без необходимой функциональности.
- В актуальной версии есть оригинальные 77 адаптеров, семантические композиции, content-review и последующие исправления карточной системы. Подмена файлов старой адаптацией потеряла бы эти изменения.
- В `build_slides.py:measure` используется `NUMBER.split(text)` без захватывающей группы: числовые фрагменты исчезают из расчёта ширины. Этот алгоритм не перенесён. В нашем измерителе добавлен регрессионный тест ширины смешанного текста и переполнения длинного числа.
- Возврат к общему пользовательскому профилю LibreOffice при ошибке не используется: он мешает изоляции и параллельным экспортам.
- Удаление метаданных Codex не перенесено. Сохранена совместимость пакета с Codex, Claude и Hermes.
- Дублировать старые 25 тестов внутри скилла не стали: актуальные тесты находятся в репозитории. Установленный пакет проверяется командами `doctor`, `validate` и контрольной сборкой.

## Что ещё стоит развить

Заметки с источниками уже есть у сборщика `/2`; оригинальный формат пока сохраняет сценарий отдельно. Унифицированные нативные заметки, адресуемые источники оригинальных адаптеров и самостоятельный короткий self-test установленного пакета остаются отдельными задачами. Этот перенос их не реализует. Каталогизатор внешних референсов пока требует Poppler и выдаёт явную ошибку, если доступен только PyMuPDF.

## Проверка этого переноса

- 59 тестов: все прошли, пропусков нет. Среди них 5 новых проверок рендера, поиска инструментов и числовой ширины.
- Отдельный экспорт 4-слайдового PPTX на macOS: PDF и 4 PNG, исходный SHA сохранился; путь результата содержит кириллицу и пробел.
- Экспорт оригинальных адаптеров при масштабе 1440: четыре PNG совпали пиксельно с прежними эталонами; средняя ошибка каждого — 0.
- Контактный лист нового экспорта просмотрен; это проверка сохранности прежнего результата, не утверждение об одобрении всех 77 композиций.
- Windows-поиск и ветка PyMuPDF проверены тестовыми подстановками. Реальный Windows-рендер и реальный PyMuPDF здесь не запускались; PyMuPDF не установлен в проверенной среде.
- Отчёт коллег о 25 тестах и 21 слайде на Windows — их заявленный результат, отдельно нами не воспроизведён.

Локальные журналы: `work/colleague-review/tests.txt`, `pixel-regression.json`, `original-render/render.json`. Они не входят в распространяемый пакет. Отсутствие визуальной регрессии на четырёх слайдах не доказывает полную поддержку произвольного наполнения.
