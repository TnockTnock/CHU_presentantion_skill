# Файлы проекта презентации

Каждая презентация — отдельная папка внутри выбранного пользователем рабочего каталога. Не сохраняй пользовательские отчёты внутри установленного скилла. Создавай только нужные каталоги.

```text
<deck-name>/
  source/                  неизменённые входные файлы или manifest путей/хешей
  content/
    outline.md             история, роль и тезис каждого слайда
    facts.json             факты, источники, расчёты, противоречия и пробелы
    deck-spec.json         актуальная спецификация контента и привязок
  design/
    template-audit.json    технический состав выбранного шаблона
    tokens.json            роли цветов, типографика, геометрия + источники
    diagrams/              редактируемые исходники / JSON узлов и связей
    assets/                использованные фото и иллюстрации
    prompts/               запросы генерации, если она применялась
  build/
    build.py или build.mjs код именно этой презентации
    dependencies.txt       фактически использованные версии и команда запуска
    intermediate/          рабочие экспорты
  preview/
    slide-001.png
    contact-sheet.png
  qa/
    report.md              проверки, исправления, ограничения
  output/
    presentation.pptx
    presentation.pdf       только после успешного экспорта и проверки
    scenario.md            тезисы, заметки, источники
```

`deck-spec.json` — вход сборщика версии `cgu-presentations/2`. Поддерживаемые поля и ограничения описаны в [builder.md](builder.md), готовый пример — `../examples/demo.json`. Старый формат с `prototype`, `bindings` и `schema_version: cgu-presentations/1` не принимается.

При сборке `run.py` создаёт `content/deck-spec.json`, `content/outline.md`, `build/template-map.json`, `output/scenario.md` и результаты проверки. `template-map.json` фиксирует исходные страницы и SHA-256. Остальные каталоги нужны только если фактически есть дополнительные источники или ассеты.

`facts.json`: стабильный id, утверждение/значение, единица, период, источник и точное место, статус (source/calculated/assumption/missing). Для расчёта — формула и id исходных фактов. В случае конфликта сохрани оба источника и основание выбора; без основания пометь неопределённость.

`outline.md` редактируется человеком; после изменения синхронизируй спецификацию. Финальный сценарий и заметки PPTX получают текст из одной актуальной версии. Не поддерживай три вручную расходящихся сценария.

Для воспроизводимости сохрани версии зависимостей, команду сборки, хеш шаблона и перечень используемых ассетов. Для локальной правки не пересоздавай остальные иллюстрации и слайды без необходимости. Не добавляй ключи API и другие секреты в проект/архив.
