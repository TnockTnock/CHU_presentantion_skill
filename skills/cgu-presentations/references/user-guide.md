# Руководство пользователя: презентации ЦГУ

Скилл `cgu-presentations` помогает AI-агенту превращать отчёты и другие материалы в презентации ЦГУ / ДИТ. Скилл — это папка с инструкциями, шаблонами, шрифтами и программой сборки. Вы ставите задачу обычным текстом; агент готовит содержание и запускает сборку.

Это руководство предназначено для пользователя. [SKILL.md](../SKILL.md) содержит рабочие инструкции для агента.

## Что входит и что получится

| В пакете | Для чего |
|---|---|
| Корпоративные PPTX-шаблоны и логотипы | Фирменное оформление ЦГУ / ДИТ |
| Golos Text Regular, SemiBold, Bold | Основной текст, заголовки и цифры |
| 12 типов слайдов | Обложка, текст, карточки, KPI, процесс, схема, график, таблица, сетка KPI, сравнение, дорожная карта, текстовые блоки |
| 6 вариантов текстовых блоков | Готовые композиции с нейтральными примерами |
| Библиотека правил и референсов | Выбор композиции без переноса чужих фактов |
| Примеры и программа сборки | Создание редактируемого PPTX и проверка структуры |
| Установщик | Копирование скилла в папку выбранного агента |

Результат: **PPTX и текстовый сценарий**. При настроенном экспорте — также **PDF и PNG каждого слайда**. Таблицы, графики и фигуры схем остаются редактируемыми. Заголовки оформляются SemiBold 600, цифры — Bold 700, основной текст — Regular 400.

Полный шаблон на 82 страницы входит как дополнительная библиотека. Автоматически заполняются поддерживаемые композиции, а не все страницы шаблона. Создание произвольного нового макета требует отдельной доработки. Импорт любого чужого PPTX с сохранением всех его особенностей не является готовой командой сборщика.

## Что нужно для работы

| Ваша задача | Требования |
|---|---|
| Обсудить структуру и тексты | Агент, который может прочитать инструкции и ваши материалы |
| Получить PPTX | Доступ агента к файлам и запуску команд; Python 3.9 или новее |
| Получить PDF и PNG | Дополнительно LibreOffice и Poppler (`pdftoppm`) |
| Проверить внешний вид | Агент с просмотром изображений или ваш просмотр слайдов |
| Редактировать PPTX на другом компьютере | Редактор презентаций и установленные шрифты Golos Text из пакета |

Для базовой сборки не нужны Node.js, установка pip-пакетов или API-ключ модели. У самого агента могут быть собственные условия доступа и тарифы. Скилл не устанавливает агент и не добавляет ему права запуска программ.

Название модели не влияет на формат сборки: GPT, Claude, Gemini или другая модель готовит содержание, а Python создаёт файл. Качество анализа источников и текста зависит от модели. [Что проверено и какие есть ограничения](portability.md#границы-проверки).

## Как получить файлы

Выберите один способ.

**Через GitHub без терминала.** Откройте [репозиторий](https://github.com/TnockTnock/CHU_presentantion_skill), нажмите **Code → Download ZIP**, распакуйте архив. Внутри найдите `skills/cgu-presentations`.

**Через Git.** Если Git установлен, выполните:

```sh
git clone https://github.com/TnockTnock/CHU_presentantion_skill.git
cd CHU_presentantion_skill/skills/cgu-presentations
```

**Из отдельного ZIP скилла.** Распакуйте полученный пакет и откройте папку `cgu-presentations`. Она должна содержать `SKILL.md`, `scripts`, `assets`, `references`, `examples` и `design-system`. Один файл SKILL.md без остальных папок недостаточен для сборки.

**Все дальнейшие команды этого руководства запускаются из папки, где лежит SKILL.md.** Откройте в ней терминал. Если используете `cd`, заключайте путь с пробелами в кавычки.

Проверьте Python:

```sh
# macOS / Linux
python3 --version
```

```powershell
# Windows, PowerShell
py -3 --version
```

Если команды нет, установите Python 3.9+ с [python.org](https://www.python.org/downloads/) или через принятый в вашей организации способ. На Windows в командах ниже заменяйте `python3` на `py -3`. Если у вас работает только `python`, используйте его после проверки версии.

## Установка в вашего агента

### Вариант 1. Поручить установку агенту

Откройте в агенте папку проекта, в которой будете делать презентации, и отправьте:

> Установи cgu-presentations из репозитория https://github.com/TnockTnock/CHU_presentantion_skill, папка skills/cgu-presentations, в текущий проект для моего агента. Прочитай references/user-guide.md. Используй scripts/skill_package.py с подходящим профилем. Проверь наличие Python и выполни demo с --backend portable --no-render в новой папке. Покажи путь к установленному SKILL.md и готовому PPTX. Если нет доступа к командам, сообщи об этом и дай команды для ручной установки.

Это поручение работает при наличии у агента доступа к репозиторию, файлам и терминалу. Если архив уже скачан, вместо ссылки укажите путь к распакованной папке.

### Вариант 2. Установить командой

Создайте отдельную папку для ваших презентаций и используйте её полный путь как `--project`. Например, `/Users/anna/Documents/Presentations` или `C:/Users/Anna/Documents/Presentations`. Не копируйте пример с чужим именем пользователя без замены.

Установка выполняется **в выбранный проект**. Затем именно этот проект нужно открыть в агенте. Она не делает скилл доступным во всех проектах на компьютере.

| Агент | Значение `--agent` | Где появится скилл внутри проекта |
|---|---|---|
| Claude Code | `claude` | `.claude/skills/cgu-presentations` |
| Cursor | `cursor` | `.cursor/skills/cgu-presentations` |
| Gemini CLI | `gemini` | `.gemini/skills/cgu-presentations` |
| GitHub Copilot с поддержкой Agent Skills | `copilot` | `.github/skills/cgu-presentations` |
| Codex | `codex` | `.agents/skills/cgu-presentations` |
| Другой совместимый агент | `generic` | `.agents/skills/cgu-presentations` |

macOS / Linux, пример для Claude Code:

```sh
python3 scripts/skill_package.py install --agent claude --project "/Users/anna/Documents/Presentations"
```

Windows, пример для Cursor:

```powershell
py -3 scripts/skill_package.py install --agent cursor --project "C:/Users/Anna/Documents/Presentations"
```

Замените профиль на нужный из таблицы. Успешный ответ содержит поле `installed` с полным путём установки. Программа создаёт копию скилла, не меняет настройки аккаунтов или системные инструкции агента.

Для установки в другую, известную вам папку клиента используйте `--dest`: это **точный путь новой папки cgu-presentations**, а не родительский каталог. `--dest` и `--project` вместе не используются.

```sh
python3 scripts/skill_package.py install --dest "/absolute/path/to/skills/cgu-presentations"
```

Пути профилей и ссылки на официальные инструкции клиентов приведены в [таблице совместимости](portability.md#подключение). Установка в локальный клиент не означает установку в веб-чат того же провайдера.

### Как включить скилл в разговоре

Откройте целевой проект в агенте. Если он не заметил новую папку, начните новую сессию или перезапустите клиент.

Универсальный запрос для любого агента:

> Используй скилл cgu-presentations из этого проекта. Сначала прочитай его SKILL.md, затем подготовь презентацию по приложенным материалам.

В Claude Code также можно вызвать `/cgu-presentations`. В Codex можно явно указать `$cgu-presentations`. Для остальных клиентов достаточно запроса с названием или точным путём к SKILL.md; специальные команды зависят от клиента.

### Веб-чаты и агенты без поддержки скиллов

Если чат позволяет загрузить ZIP и выполнять Python, загрузите **полный пакет** и попросите распаковать его, прочитать SKILL.md и запустить portable-сборку. Не все продукты поддерживают такое выполнение. Загрузка ZIP сама по себе не является установкой скилла в аккаунт.

Если агент может читать файлы и запускать команды, но не распознаёт скиллы, укажите полный путь к SKILL.md вручную. Если доступен только текстовый чат, он может подготовить структуру и спецификацию; собрать PPTX нужно в среде с Python. Не требуйте от такого чата ссылку на файл, который он не создавал.

## Первая проверка

Из исходной папки скилла выполните (на Windows замените `python3` на `py -3`):

```sh
python3 scripts/run.py doctor --backend portable
python3 scripts/run.py demo --backend portable --no-render --out "../cgu-demo-01"
```

`doctor` показывает доступность ресурсов. Пустой список `resources.errors` означает, что ресурсы прошли проверку. `render_available: false` допустимо для PPTX без PDF.

Команда `demo` создаст демонстрацию на 7 слайдов. Откройте `../cgu-demo-01/output/presentation.pptx`. Итог сборки должен содержать `structure: passed`. `visual_review: pending` ожидаемо: автоматическая структурная проверка не заменяет просмотр слайдов.

Для повторного запуска используйте новую папку, например `../cgu-demo-02`. Не удаляйте свою предыдущую презентацию ради повторной проверки.

## Создание своей презентации

Обычно писать JSON и запускать команды самостоятельно не нужно. Дайте агенту материалы и задачу. Сохраните отчёты в отдельной папке проекта, например `source/`, или приложите их в чате, если агент имеет доступ к вложениям.

Укажите аудиторию, цель, объём, исходные материалы и желаемый результат. Если исходные данные неполные, обозначьте, какие вопросы агент должен оставить открытыми.

**Презентация из отчёта:**

> Используй cgu-presentations. По отчёту source/report.docx подготовь 8 слайдов для руководства ДИТ: результаты, ключевые показатели, проблемы и следующие шаги. Используй фирменный шаблон и редактируемые схемы. Не придумывай отсутствующие показатели. Сохрани результат в новой папке results/report-v1. Нужны PPTX и сценарий, а при доступном рендерере — PDF и превью. Проверь каждый слайд и перечисли непроверенные пункты.

**Сначала структура:**

> Используй cgu-presentations. Изучи приложенные материалы и предложи структуру на 6 слайдов: заголовок, главный тезис, источник и подходящая композиция. Пока не собирай файл.

**Схема процесса:**

> Используй cgu-presentations. По описанию source/process.md сделай слайд с редактируемой схемой: участники, этапы и подписанные связи. Не добавляй переходов, которых нет в описании. Сохрани PPTX в новой папке results/process-v1.

**Нейтральные шаблоны:**

> Используй cgu-presentations. Собери шесть вариантов текстовых блоков из examples/text-blocks-demo.json. Сохрани нейтральные тексты и демонстрационные показатели; не переноси сведения из наших рабочих презентаций.

Агент изучает источники, готовит структуру, выбирает композиции, формирует JSON и собирает презентацию. Для реальных материалов нужны ссылки на источники; демонстрационный режим предназначен для вымышленных примеров. Поддержка чтения PDF, DOCX или таблиц определяется инструментами самого агента: сборщик принимает подготовленный JSON, а не исходный отчёт.

## Где результат и как его изменить

В папке, которую вы указали для результата:

| Путь | Что внутри |
|---|---|
| `output/presentation.pptx` | Редактируемая презентация |
| `output/scenario.md` | Сценарий и заметки |
| `output/presentation.pdf` | PDF, только после экспорта |
| `preview/slide-*.png` | Изображения слайдов, только после экспорта |
| `content/deck-spec.json` | Содержание и настройки слайдов для повторной сборки |
| `content/outline.md` | Краткая структура |
| `qa/report.md`, `qa/run.json` | Результаты проверок и ограничения |

Для правок отправьте агенту:

> Открой results/report-v1/content/deck-spec.json. На слайде 3 сократи пояснение, а слайд 5 раздели на два. Сохрани исходные показатели и источники. Собери новую версию в results/report-v2 и проверь её.

Изменения вручную в PowerPoint не возвращаются автоматически в JSON. Для последующих пересборок попросите агента синхронизировать содержание. Полная схема файлов проекта описана в [project-contract.md](project-contract.md).

## PDF, превью и шрифты

PPTX собирается с `--no-render` без внешних программ. Для PDF/PNG нужны LibreOffice и Poppler с командой `pdftoppm`, доступные **там, где запускается агент**, а не только на вашем компьютере. Если программы не найдены, `doctor --backend portable` покажет отсутствие рендерера.

Установите программы принятым для вашей ОС способом: [LibreOffice](https://www.libreoffice.org/download/download-libreoffice/) и [Poppler](https://poppler.freedesktop.org/). Poppler распространяется также через пакетные менеджеры; на Windows доступность сборки уточняйте у администратора среды. Скилл не устанавливает эти программы автоматически.

Если программы есть, но не находятся в PATH, задайте пути к исполняемым файлам:

```sh
# macOS / Linux: замените оба пути на реальные
export CGU_SOFFICE="/absolute/path/to/soffice"
export CGU_PDFTOPPM="/absolute/path/to/pdftoppm"
```

```powershell
# Windows: замените оба пути на реальные
$env:CGU_SOFFICE = "C:/path/to/soffice.exe"
$env:CGU_PDFTOPPM = "C:/path/to/pdftoppm.exe"
```

Переменные действуют в текущем терминале и запущенных из него процессах. В Codex при наличии комплектного рендерера используется он. Повторите `doctor`, затем сборку без `--no-render`:

```sh
python3 scripts/run.py demo --backend portable --out "../cgu-demo-pdf-01"
```

Для просмотра и редактирования PPTX установите три файла `.ttf` из `assets/fonts` средствами вашей ОС. Шрифты в PPTX **не встроены**. При рендеринге на Linux/macOS сборщик передаёт локальную конфигурацию шрифтов; на Windows может потребоваться их установка в системе. Проверьте внешний вид готового PDF перед отправкой.

## Обновление и перенос

Скачайте свежую версию или выполните `git pull --ff-only` в чистой Git-копии репозитория. Если Git сообщает о локальных изменениях, сначала сохраните их; не сбрасывайте их ради обновления.

Откройте папку свежего скилла и повторите установку с тем же профилем и проектом, добавив `--replace`:

```sh
python3 scripts/skill_package.py install --agent claude --project "/Users/anna/Documents/Presentations" --replace
```

Установщик сохранит предыдущую версию в резервной папке и покажет её путь в поле `backup`. Персональная папка `local/` переносится в новую установку. Другие ваши изменения останутся в резервной копии; автоматически они не объединяются. Затем начните новую сессию агента и повторите первую проверку.

Обновление репозитория само по себе **не обновляет установленную копию**. При нескольких установках обновите каждую нужную папку.

Для передачи пакета коллеге выполните из папки скилла:

```sh
python3 scripts/skill_package.py pack --out "../cgu-presentations.zip"
```

Имя ZIP должно быть новым. В архив попадут инструкции, шаблоны, шрифты и нейтральные примеры; личная `local/`, рабочие результаты и исходные референсы исключаются. Внутри архива руководство находится в `cgu-presentations/references/user-guide.md`.

Личная библиотека реальных презентаций не переносится автоматически. Её подключение описано в [library.md](library.md). Оригиналы отчётов и рабочие презентации храните вне установленного скилла. Правила использования корпоративных шаблонов и логотипов определяет правообладатель; лицензия шрифта находится в `assets/fonts/OFL-GolosText.txt`.

## Если что-то не работает

| Ситуация | Что сделать |
|---|---|
| Агент не видит скилл | Откройте именно проект установки, проверьте путь к SKILL.md, начните новую сессию или укажите путь явно |
| Скилл скопирован, но файл не создаётся | Проверьте доступ агента к терминалу и Python; установка инструкций не даёт права выполнения |
| `python3` не найден | Windows: попробуйте `py -3`; иначе установите Python и проверьте версию |
| Не найден `scripts/run.py` | Перейдите в папку с SKILL.md; не путайте корень Git-репозитория и папку скилла |
| `Skill exists` | Для обновления используйте `--replace`; сначала учтите свои изменения в старой копии |
| Папка результата уже занята | Укажите новую папку через `--out`, например `report-v2` |
| Нет LibreOffice / Poppler | Создайте PPTX с `--no-render` или настройте программы для PDF/PNG |
| Шрифт выглядит иначе | Установите все три начертания Golos Text на компьютере просмотра |
| Ошибка переполнения текста | Сократите текст или разделите слайд; не уменьшайте шрифт ради вместимости |
| Ошибка источников или полей JSON | Попросите агента исправить спецификацию по [builder.md](builder.md); не маскируйте реальные данные как demo |
| `visual_review: pending` | Нужно просмотреть все превью; это не ошибка создания PPTX |
| Нет подходящего макета | Используйте поддерживаемую композицию либо поручите отдельное расширение скилла |

Для диагностики передайте агенту точную команду, текст ошибки, ОС, версию Python и вывод `doctor --backend portable`. Не отправляйте исходные внутренние отчёты в публичные обсуждения ошибок.

## Для тех, кто запускает сборку вручную

```sh
python3 scripts/run.py validate "/absolute/path/to/deck.json"
python3 scripts/run.py build "/absolute/path/to/deck.json" --backend portable --no-render --out "../my-deck-v1"
```

JSON должен соответствовать формату `cgu-presentations/2`. Начните с [examples/demo.json](../examples/demo.json); поля и ограничения описаны в [builder.md](builder.md). `portable` явно выбирает Python-сборку, `codex` требует специального окружения Codex, `auto` выбирает доступный движок. Для одинакового способа сборки между агентами используйте `portable`.
