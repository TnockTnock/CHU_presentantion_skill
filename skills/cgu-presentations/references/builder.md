# Сборщик и контракт данных

Общий CLI поддерживает два движка. `portable` использует только Python 3.9+ и редактирует OOXML-копию корпоративного шаблона. `codex` использует `@oai/artifact-tool` и finalizer из установленного Presentations runtime. `auto` сохраняет прежний выбор в Codex и использует portable вне него. Установка и требования: [portability.md](portability.md).

## Запуск

`SKILL_DIR` — абсолютный путь к папке, содержащей этот SKILL.md. Рабочая папка презентации должна быть новой/пустой.

```bash
python3 "$SKILL_DIR/scripts/run.py" doctor
python3 "$SKILL_DIR/scripts/run.py" demo --out work/demo-01
python3 "$SKILL_DIR/scripts/run.py" build deck.json --out work/presentation-01
```

По умолчанию сборка выдаёт PPTX, PDF, PNG каждого слайда, сценарий, копию входной спецификации и отчёты. Результат в `output/`, изображения в `preview/`, проверки в `qa/`. `--no-render` пропускает PDF/PNG и оставляет визуальную проверку незавершённой. Повторный запуск в непустую папку запрещён для защиты результатов.

Только для backend `codex`: если пути runtime не находятся и инструмент доступен, вызови инструмент `load_workspace_dependencies`, затем передай `--runtime <dependencies>` и `--presentation-skill <папка навыка Presentations>`. Эквивалентные переменные: `CGU_RUNTIME_DIR` и `CGU_PRESENTATIONS_SKILL`. В Codex для PDF применяется bundled `soffice`. В portable вне Codex укажи `CGU_SOFFICE`/`CGU_PDFTOPPM` либо установи программы в PATH.

## Поддерживаемый формат

Полный пример: `examples/demo.json`. Корень: `schema_version: "cgu-presentations/2"`, `title`, `demo` (булево), `sources: [{id, location}]`, `slides`. У каждого слайда обязательны `id`, `kind`, `title`; опциональны `notes`, `footer`, `source_ids`. В недемонстрационном режиме ссылки на источники обязательны. В деморежиме каждый слайд автоматически получает видимую пометку.

| kind | Поля | Пределы |
|---|---|---|
| cover | subtitle | Обложка из страницы 6 короткого шаблона |
| cards | items: [{title, body}] | Ровно 4 карточки, страница 8 |
| kpi | value, label, detail_title, detail | 1 показатель, адаптация страницы 15 |
| text | body | До 650 символов в оболочке страницы 14 |
| process | steps: [{title, body}] | 2–5 шагов, нативные узлы и стрелки |
| diagram | nodes: [{id, text, box, accent?}], edges: [{from, to, from_side?, to_side?}] | 2–8 узлов, связанные connectors |
| chart | chart_type?: bar/line, unit, categories, series: [{name, values}] | 2–10 категорий, 1–3 ряда, нативный chart с workbook |
| table | columns, rows | 2–4 столбца, 1–7 строк, нативная таблица |

`diagram.box` — `[x,y,w,h]` в CSS px на холсте 1920×1080. Безопасная область: x=100…1820, y=270…920. Стороны соединения: left/right/top/bottom. Направление from → to проверяется по связанным shape id и стрелке на целевом конце. Подписи задаются полями `label` и `label_box`, описанными ниже. Для сложного графа требуется ручная проверка маршрутов: автоматическая раскладка не заявлена.

Лимиты символов — ранний фильтр. При сборке дополнительно измеряется текст реальными метриками Golos; переполнение блокирует сборку. Автоподгонка уменьшением кегля не включается. Раздели содержание, если оно не помещается.

Данные графиков записываются в нативный chart и новый workbook snapshot. Исходные формулы Excel не сохраняются этим форматом. Поля должны содержать фактические значения: например для долей используйте выбранную единицу последовательно; автоматического преобразования 0,8 в 80% нет. Нули и отрицательные значения сохраняются. Таблицы принимают строки, чтобы агент явно контролировал русское форматирование.

## Границы реализации

Автоматический адаптер проверен для конкретных страниц **короткого** шаблона. `design-system/layouts.json` связывает роли с SHA-256; смена шаблона блокирует сборку до адаптации. Полный шаблон сохранён как библиотека других композиций, но автоматическое заполнение всех его 82 страниц не реализовано.

Произвольные изображения и новые макеты требуют расширения кода агентом с повторной визуальной проверкой. Не добавляй выдуманные поля в JSON: неизвестные поля отклоняются. Для генерации отдельной иллюстрации используй правила `diagrams.md`, затем явное расширение сборки.

`normalize_fonts.py` удаляет несовместимые старые embedded fonts из рабочей копии и назначает Golos Text / Golos Text SemiBold. Исходные PPTX не меняются. Новые TTF не встраиваются в PPTX автоматически; для редактирования у получателя должны быть установлены шрифты из `assets/fonts`. PDF рендерится с этими шрифтами и проверяется по font inventory.

## Проверки

`run.py` выполняет проверку входа, сборку, аудит шрифтов/relationships и проверку семантики: узлы и направления рёбер, значения charts, наличие workbook и ячейки таблиц. Backend `codex` дополнительно выполняет finalizer и повторный импорт. Portable фиксирует собственный движок проверки в `qa/run.json`; не выдаёт его за Codex finalizer. Отдельный запуск проверки:

```bash
python3 "$SKILL_DIR/scripts/verify_output.py" deck.json work/presentation-01/output/presentation.pptx
```

После успешной команды агент обязан посмотреть все PNG. `qa/run.json` сохраняет `visual_review: pending`: это поле нельзя автоматически превращать в passed только по наличию файлов. После реального просмотра запиши наблюдения и хеш проверенного PPTX в отчёт.

## Расширение библиотеки

Исполняемые привязки теперь находятся в `design-system/layouts.json`, общие параметры — в `design-system/tokens.json`. Перед сборкой `preflight.py` проверяет SHA, слоты, логотипы, наличие layout relationship и соответствие типов. `spec.py` остаётся исполняемым контрактом; отдельной расходящейся JSON Schema нет.

Дополнительные типы (пример: `examples/library-demo.json`):

| kind | Поля | Вместимость |
|---|---|---|
| `kpi_grid` | `items: [{value, label, detail}]` | 2–4 показателя; 12/65/130 символов |
| `comparison` | `columns: [{title, items: [text]}]` | 2 колонки, одинаковое число строк 2–4 |
| `roadmap` | `steps: [{title, period, body}]` | 3–6 этапов; 38/25/100 символов |

Roadmap показывает порядок, но не длительность: ширина этапов одинакова. Для Ганта нужен отдельный адаптер с датами и общей временной шкалой.

В `diagram.edges` дополнительно разрешены `label` и `label_box: [x,y,w,h]`. Они задаются вместе. Подпись — отдельный редактируемый текст, до 60 символов; коробка внутри безопасной области и вне узлов. Автоматика не гарантирует отсутствие пересечений с маршрутом стрелки, поэтому нужен визуальный просмотр.

## Источники отдельных объектов

Формат `/2` сохраняет совместимость. Новое необязательное поле корня `evidence_policy` принимает `slide` (старый режим) или `object`. У слайда можно указать:

```json
"source_ids": ["report-1"],
"object_sources": {"/value": ["report-1"]}
```

Это простые JSON pointers внутри слайда. Для KPI используется `/value`, для `kpi_grid` — `/items/0`, для графика — `/series/0`, для схемы — `/edges/0`, для roadmap — `/steps/0`. В режиме `object` все такие объекты фактической презентации обязаны иметь ссылки. Для текста и сравнений можно привязать другие существующие содержательные поля.

Источник содержит `id`, `location` и необязательный `status`: `source`, `calculated`, `assumption`, `conflict`. Расчёту нужна `formula`. `conflict` нельзя назначить доказательством объекта, пока противоречие не разрешено. Существование файла, правильность формулы и подтверждение утверждения проверяются агентом по первоисточнику: сборщик валидирует только структуру ссылок. Предположение обозначай в видимом содержании/заметках.

Ссылки включаются в заметки, `output/scenario.md` и `content/sources.json`. `qa/run.json` отдельно отражает проверку структуры, ссылок, фактов, рендера и PowerPoint; успешная сборка не ставит `visual_review: passed` автоматически.

## Текстовые блоки

`kind: "text_blocks"`, `variant`, `items: [{title, body}]`; для `metrics_band` у каждого элемента также `value`. Плашка `callout` обязательна для `columns_callout`, `split_panel`, `metrics_band` и не принимается в остальных вариантах. Вместимость и выбор — [text-blocks.md](text-blocks.md). Пример: `examples/text-blocks-demo.json`.

В режиме `evidence_policy: "object"` у фактических текстовых блоков нужны ссылки `/items/0`, `/items/1` и далее, плюс `/callout`, когда он присутствует. Нейтральные шаблоны используют `demo: true`.

После нормализации шрифтов `number_typography.py` применяет Bold 700 к цифрам. `verify_output.py` проверяет числовые runs и заголовки, а также наличие нативного текста новых блоков. Рабочие оригиналы не изменяются.

## Строгая редакционная проверка и новые композиции

Формат `/2` расширен опциональными review_policy/content_ledger и редакционными полями слайдов. [Контроль содержания](content-review.md), [композиции](semantic-layouts.md), машинные схемы в `schemas/`. Предел — 160 слайдов с учётом приложений. Старые спецификации сохраняют прежний режим. Новые композиции исполняются portable; auto выбирает его по возможностям до сборки.
