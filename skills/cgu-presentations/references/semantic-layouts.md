# Исполняемые смысловые композиции

Новый адаптер `kind: "composition"` дополняет прежние 12 типов. Он содержит 20 именованных композиций. Все используют корпоративный шаблон, исходные логотипы, цвета из tokens.json и Golos Text. Это адаптации принципов утверждённой библиотеки, а не утверждение о точном воспроизведении её страниц.

Машинный каталог: `design-system/semantic-layouts.json`. В нём для каждой композиции указаны reference_key, назначение, семейство сетки, минимальное/максимальное число элементов, обязательные поля, ограничения длины, безопасная область, типографика и тестовый пример. `reference-patterns.json` остаётся каталогом визуальных принципов: reference-only не означает исполняемый макет.

| layout | Назначение | Элементы |
|---|---|---|
| timeline_horizontal | События слева направо, равные интервалы чтения | 2–5 |
| timeline_vertical | Компактная программа по строкам | 2–5 |

## Контракт

Общие поля слайда сохраняются. Добавляются `layout`, `items`, `takeaway`, `caveat`; редакционные поля описаны в [content-review.md](content-review.md). У каждого элемента `heading` и `body`; поддержка `label`/`value` зависит от композиции и фиксируется в каталоге. Длины — верхний предел контракта, а не гарантия вместимости: длинные слова и переносы проверяются по метрикам шрифта.

Пример:

```json
{
  "id": "process", "kind": "composition", "layout": "human_loop",
  "title": "Контроль решения", "takeaway": "Ответственность сохраняется за человеком",
  "caveat": "Предлагаемая схема; границы делегирования требуют согласования",
  "intent": "process", "statement_type": "analysis",
  "selection_reason": "Нужно показать распределение действий и возврат на доработку",
  "source_ids": ["s1"],
  "items": [
    {"heading": "ИИ", "body": "Готовит предложение"},
    {"heading": "Человек", "body": "Проверяет и принимает решение"},
    {"heading": "Результат", "body": "Фиксируется после проверки"}
  ]
}
```

У decision_tree обязательны `connections: [{"from": 0, "to": 1}]`, индексы соответствуют items. У карт поле `center` задаёт общий предмет. Связи карт означают принадлежность, а не причинность. У временных шкал расстояния не кодируют длительность: это порядок событий с явными датами/временем. Для причинного вывода нужны соответствующие источники.

У speaker_profile опционально `image: {path, sha256, source_id, alt, identity_status}`. PNG/JPEG вставляется целиком с сохранением пропорций; `identity_status` — `source-caption` или `verified`. Наличие подписи в исходном файле не доказывает личность независимо. Пути к изображениям задаются относительно JSON. Используй проверенные оригиналы, не генерируй фотографии реальных спикеров или логотипы. Для вендоров без достоверных логотипов используй текстовые названия и зафиксируй ограничение.

## Сборка и проверка

```sh
python3 scripts/run.py build examples/semantic-demo.json --backend portable --out ../semantic-demo
```

Новые композиции реализованы в portable. `auto` выбирает portable для них; явный `codex` выдаёт понятную ошибку. Прежние типы по-прежнему работают в обоих движках. Это ограничение движка, а не агента: portable доступен всем профилям с Python.

Все текстовые поля, связи и таблицы остаются нативными. Фото — отдельный объект изображения с исходными байтами. Проверка сравнивает текст, таблицы, направления связей и SHA изображения с заданием.

Автоматический QA проверяет текст по метрикам Golos, выход за границы слайда, мелкий текст новых объектов, явные цвета, заглушки и подозрительные пересечения текстовых рамок. Контроль обрезки изображений предупреждает о srcRect. Неровные отступы, маршруты связей, фактические переносы и оптическое равновесие необходимо проверить на каждом PNG. Не присваивай статус visual passed автоматически.
