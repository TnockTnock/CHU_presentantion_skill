# Библиотека референсов и исполняемые макеты

## Где находится истина

- `design-system/layouts.json`: единственный исполняемый реестр. У каждого типа — ключ, SHA шаблона, исходная часть/страница, слоты с shape id, сохраняемые фигуры, логотипы, вместимость, превью и отдельные статусы. Сборщик и проверка логотипов читают этот файл.
- `design-system/tokens.json`: шрифты, основные цвета, размеры заголовков и геометрия. Значения текущего адаптера сохранены для совместимости. В provenance прямо отмечены параметры реализации; они не выдаются за извлечённые универсальные правила брендбука.
- `design-system/reference-patterns.json`: обезличенные наблюдения по 10 семействам реальных композиций. `builder_kind: null` означает, что это только референс. Наличие `builder_kind` означает адаптированный или общий способ сборки, а не точную копию.
- Локальный `catalog.json`: пути, хеши, текст, страницы, дубли и превью оригиналов. `curated.json` связывает отобранные композиции с конкретными источниками. Эти файлы не публикуются.

## Как использовать

```bash
python3 "$SKILL_DIR/scripts/search_references.py" "roadmap" --limit 5
```

Путь определяется из `--catalog`, `CGU_REFERENCE_LIBRARY` либо персонального `local/reference-library.json` с полем `catalog_path`. Если каталога нет, используй переносимые описания и синтетические превью; не придумывай исходник.

После поиска открой превью выбранной страницы. Проверь иерархию, вместимость и пригодность для текущего материала. Цифры, персональные данные, подписи и иллюстрации референса не являются содержанием нового документа.

## Пополнение

Запускай bundled Python с pypdf и Pillow:

```bash
"$RUNTIME_PYTHON" "$SKILL_DIR/scripts/catalog_references.py" <папка> --out <новая локальная папка> --runtime "$RUNTIME_DIR"
```

Сканируются PDF и PPTX; остальные файлы учитываются в статистике, но не превращаются автоматически в слайды. Исходники не изменяются. PDF рендерится Poppler, PPTX сначала bundled LibreOffice; desktop LibreOffice не используется. Рендер оригинала может подменить отсутствующий шрифт. Сравни с исходным PowerPoint, прежде чем считать его точным типографическим образцом.

Удаляются только точные дубли файлов и совпадения пикселей при выбранном разрешении. Похожие версии сохраняются: разница может быть содержательной. Пустые кадры, видео и интерфейсные скриншоты остаются в каталоге, но не становятся макетами автоматически.

## Статусы и переход к адаптеру

1. `unreviewed`: извлечено автоматически.
2. `contact-sheet-triage`: просмотрена обзорная композиция; текст и качество каждой страницы не сертифицированы.
3. `reference-reviewed`: выбранная страница просмотрена отдельно; пригодна как образец композиции.
4. В исполняемом реестре отдельно: `binding_status: implemented`, `visual_status: verified-demo`, `powerpoint_status: not-tested` либо фактический результат проверки.

Для нового адаптера нужны: нейтральный пример на Golos, карта слотов, безопасные области, валидация содержания, проверка редактируемости и рендер. Поля полной библиотеки PPTX не считаются поддержанными только потому, что найдены в архиве. Изменение SHA шаблона требует повторной проверки привязок.

Проверка источников: хранить путь/хеш/страницу локально; для переносимого пакета оставлять только нейтральное описание и синтетический образец. Не копировать исходный PDF или screenshot с данными в `design-system/previews/`.
