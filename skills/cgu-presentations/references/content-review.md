# Сохранность содержания и смысловой выбор

Для переработки содержательной презентации используй `review_policy: "strict"`. Старые `/2` спецификации без этого поля остаются совместимыми. Строгий режим требует журнала содержания и редакционных полей каждого слайда.

## Сначала инвентаризация

```sh
python3 scripts/content_review.py source.pptx --out source-inventory.json
```

Извлечение следует порядку слайдов PPTX. Каждому непустому абзацу присваивается стабильный id, текст и указатель на слайд/абзац. SHA исходника и архива позволяют заметить подмену. Это инвентаризация **текстовых фрагментов**, а не доказательство того, что автоматически выделены все атомарные факты: проверь составные утверждения, таблицы, графики и сведения на изображениях отдельно. Для другого документа подготовь такой же inventory вручную с точными страницами/ячейками; не заявляй об автоматическом извлечении неподдерживаемого формата.

В корне спецификации укажи `content_ledger`:

```json
{
  "inventory": "source-inventory.json",
  "inventory_sha256": "SHA256 файла inventory",
  "entries": [{
    "fact_id": "s2-p10",
    "status": "appendix",
    "reason": "Полная формулировка нужна для сверки, в основной части дан краткий вывод",
    "statement_type": "source_report",
    "targets": [{"slide_id": "appendix-02", "pointer": "/body", "text": "Точный текст фрагмента"}]
  }]
}
```

Статусы: `preserved` — сохранён; `condensed` — сокращён; `appendix` — перенесён в приложение; `excluded` — исключён. Причина обязательна всегда. Сохранённый фрагмент должен совпадать с видимым текстом. Сокращение допускает перефразирование, но требует точного указателя на результат и содержательной проверки. Для приложения нужен `section: "appendix"`. Ссылка на notes вместо содержимого слайда не считается сохранением. Исключение не может иметь назначений.

Сборка блокируется при пропущенных/повторных id, изменённом SHA, исчезнувшем тексте назначения и попытке спрятать сохранённый факт в заметках. Полнота относительно inventory не доказывает истинность фактов или смысловую эквивалентность сокращений.

## Показатели как целая конструкция

Для новых KPI используй `composition` с `layout: hero_kpi` или `metric_scale` и `metric_bindings`. Пример:

```json
{
  "pointer": "/items/0/value",
  "metric": {
    "number": "10", "sign": "", "currency": "$", "scale": "трлн", "suffix": "",
    "display": "$10 трлн", "unit": "капитализация участников", "period": "2026",
    "explanation": "Совокупная оценка", "source_id": "s2", "source_text": "$10 трлн"
  }
}
```

`display` составляется из знака, валюты, числа, масштаба и суффикса; весь display находится в одном текстовом объекте. Единица, период и пояснение должны присутствовать в видимом содержании. Если период не дан, явно укажи «период не указан». Не добавляй вымышленную дату. Сборщик сверяет display с привязанным полем и исходным числовым фрагментом. При наличии inventory он проверяет присутствие source_text в архиве. Семантическое соответствие источника периоду и единице проверяет агент.

В strict-режиме старые `kpi`/`kpi_grid` также требуют bindings. Если полное число с единицей не помещается в прежнее поле, выбери новую композицию, а не отрезай «млн» или «трлн».

## Факт, цитата и интерпретация

`statement_type`: `verified` (проверенный факт), `quote` (цитата), `source_report` (пересказ), `analysis` (аналитический вывод), `question` (вопрос к позиции). Для `verified` каждому источнику нужны `verified_at` и `verification_url`. Это запись проверки, а не автоматическая верификация сайта.

На смешанном слайде обозначай статус рядом с соответствующим утверждением. У `composition` обязательна видимая `caveat`; не называй проверенным то, что известно только из исходной презентации. Для цитат сохраняй автора, дату, точную формулировку и оговорку происхождения. Авторство и актуальность участия спикера — разные проверки.

## Один смысл и допустимые композиции

В strict-режиме каждый слайд содержит `intent`, `takeaway`, `statement_type`, `selection_reason`. `intent`: metrics, comparison, sequence, hierarchy, process, causality, decision, profile или reference. `takeaway` — главный вывод либо главный вопрос; для справочной страницы достаточно роли страницы, не выдумывай аналитический вывод.

`layout_selector.py` предлагает до трёх вариантов по смыслу и вместимости. Альтернативный базовый адаптер может требовать перестройки полей; это не обещание автоматической конвертации. Перед выбором оцени длину текста, соседние композиции и источники связей. Отчёт сохраняется в `qa/visual-diversity.json`.

Три одинаковые сетки подряд вызывают предупреждение. Одинаковые линейные сетки учитываются совместно даже при разных смысловых названиях. Для оправданной серии таблиц, профилей или документального приложения запиши `repeat_reason` у каждого слайда серии. Причина должна объяснять задачу, а не маскировать монотонность.

## Раздельные результаты

- `output/scenario.md` — выводы и краткие заметки выступающему, без дампа JSON.
- `content/sources.json` — журнал источников.
- `content/source-archive.json` — точный архив исходного текста.
- `qa/content-ledger.json` и `.md` — решения по каждому фрагменту.
- `qa/visual-checks.json` — геометрия, типографика, цвет и подозрительные пересечения.
- `preview/contact-sheet.html` — контактный лист после рендера; JPEG-листы создаются при наличии Pillow.

В PPTX notes остаются краткие заметки докладчика и ссылки на источники. Не вставляй туда полный исходный слайд. Наличие архива или журнала не заменяет видимое сохранение существенных оговорок.
