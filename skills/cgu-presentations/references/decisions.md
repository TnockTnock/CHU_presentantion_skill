# Основания архитектуры и миграция

Исследование: 23.09.2026. Это зафиксированные наблюдения и проектные решения, а не утверждение, что весь старый сборщик уже перенесён.

## Локальные источники

- `cgu-presentation-builder/SKILL.md` и `scripts/`, `references/`, `brand/tokens.json` — прежняя реализация.
- `Шаблон презентации/` — два PPTX, методички PowerPoint и Figma. Копии PPTX и хеши поставляются в `assets/templates/manifest.json`.
- Методичка PowerPoint: Golos Regular/Demibold, минимум 12 pt, до трёх размеров, сохранение фирменных макетов и редактируемого PPTX, экспорт PDF. Инструкции по подключению Figma описывают ручной процесс; они не требуют создавать Figma-файл для каждой презентации.

## Наблюдения → решения

| Наблюдение | Решение |
|---|---|
| Старый каталог: 87 страниц, 720×405 pt; новые: 82/19, 1440×810 pt | Нельзя передать новый файл в `--template` со старым каталогом. Новый аудит и новые привязки |
| Полная версия наследует многое из 77 layouts и 12 masters | Читать цепочку slide → layout → master → theme, не только текст slides |
| В темах новых файлов Calibri/Aptos, в одном layout `Intro Bold Regular` | Нормализовать рабочую копию и проверять шрифты после экспорта |
| В старом скилле Intro; portable переключает его на Montserrat | Для новой версии единое семейство Golos Text, включая KPI |
| Прежний `cgulib.py` измеряет Intro метриками Montserrat | Не переносить проверки переполнения без новых метрик/начертаний |
| Старая палитра не описывает однозначно все цвета нового файла | Выводить токены по ролям из выбранных макетов и фиксировать источники |
| В новой подборке есть плоские и 3D-иконки | Не наследовать запрет плоских иконок |
| Старый сборщик поддерживает bar/hbar/donut/table, произвольного графа связей нет | Разделить схемы и количественные диаграммы; сборку схем делать нативными объектами |
| Старые bar/hbar имеют минимальную геометрическую величину | Не использовать без доработки для нулей/малых значений/отрицательных чисел |

## Внешний источник

Изучены [README](https://github.com/ningzimu/codex-ppt-skill/blob/main/README_en.md) и [SKILL.md](https://github.com/ningzimu/codex-ppt-skill/blob/main/skills/codex-ppt/SKILL.md).

Там конечный слайд — одна сгенерированная картинка. Берём идею отдельного проекта, сценария, репрезентативного образца, сохранения ассетов и поэтапного контроля. Для ЦГУ выбран гибрид: оболочка шаблона + редактируемые данные и схемы + отдельные иллюстрации. Это наш проектный выбор, а не возможность, заявленная внешним репозиторием. Его обязательные согласования, субагенты и правила image-only в этот скилл не перенесены. Код и текст внешнего репозитория не копируются.

## Что можно переиспользовать после адаптации

Редактуру контента, реестр источников, формат сценария, подход к просмотру контактного листа и библиотеку Golos Text. Старые скрипты содержат полезную механику, но привязаны к иной геометрии и каталогу. Ресурсы не копируются целиком, чтобы не оставить конфликтующие правила.

## Следующий инженерный этап при развитии автоматизации

1. Извлечь каталог ролей/полей из новых layouts и эталонные превью с корректными шрифтами.
2. Реализовать нормализацию Golos с сохранением весов и метрик.
3. Перенести сборку на привязки часть+placeholder/shape, отказать при несовпадении хеша шаблона.
4. Добавить нативные узлы/соединения и количественные графики с корректными шкалами.
5. Проверить полный цикл на короткой демонстрации: обложка, текст, KPI, процесс, архитектура, график данных.

Текущий пакет — единый процедурный скилл с шаблонами и проверяемым аудитом. Универсальный сборщик и каталог всех слотов новой версии не реализованы. Процедурная сборка агентом возможна по правилам скилла; надёжность автоматической миграции старого движка пока не подтверждена.
