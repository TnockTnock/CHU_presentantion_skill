# Оригинальный шаблон: выбор, сборка и проверка

Сначала прочитайте [карточную систему](card-system.md): она уточняет визуальные требования по Figma и обратной связи пользователя.

Это основной путь для презентаций по корпоративным композициям. Сборщик переносит исходные объекты PPTX и наследование layout → master → theme. Не перерисовывайте их похожими карточками.

## Что входит

Источник — `assets/templates/cgu-full.pptx`, SHA-256 `ff2b8630acc36d1fd65ae0bda7cbb739ec8405997b2723a38d52efd15611497b`.

Инвентаризация: 82 слайда, 77 макетов, 12 образцов. Слайды 1–3 — инструкции, 4–5 — иконки, 6–82 — 77 кандидатов с реализованными контрактами полей. Они объединены в 18 семейств; 76 сигнатур геометрии не означают 76 уникальных дизайнов. Геометрические варианты и различия исходных объектов сохраняются в реестре.

Откройте [каталог](../assets/catalog/original/index.html). Каждая карточка содержит исходный номер, нейтральный пример, назначение, семейство, поля, ограничения, расположение и цепочку наследования. Машинный реестр — `design-system/original-layouts.json`, таблица покрытия — `assets/catalog/original/coverage.csv`. Контактные листы находятся в `assets/catalog/original/{previews,examples}/`.

## Как пользоваться

1. Подготовьте аудиторию, цель, outline и источники по `project-contract.md` и `content-review.md`. Контрольный пример содержит вымышленные данные, не переносите их в рабочую презентацию.
2. Выберите intent: reference, comparison, sequence, process, hierarchy, metrics, profile, decision. Получите 2–3 кандидата, затем откройте превью и проверьте конкретные поля:

```bash
python3 scripts/run.py original-select metrics --fields 3 --data-type chart
python3 scripts/run.py original-select process --fields 4 --previous-family path
```

Селектор фильтрует тип данных и оценку вместимости. Он не доказывает содержательную пригодность; число полей не равно числу смысловых блоков. Пустой результат требует другого intent или расширения адаптера.

3. Создайте `content/deck-spec.json` по `schemas/original-deck.schema.json`. Возьмите нужные записи из `examples/original-all.json`, сохраните `layout_id` и точные ключи `fields`. Слайды можно переставлять и повторять с уникальными `id`. Обязательные поля нужно заполнить; защищённые менять нельзя. Необязательное изображение можно не передавать: останется исходная графика или пустая область.
4. Для изображений задайте `path`, `sha256`, `alt`. PNG/JPEG размещается в исходной области с центральным кадрированием и исходной маской. Проверьте, что важные детали не обрезаны. Таблица поддерживает до 5 столбцов и 6 строк данных. Нативный график bar/line — до 3 рядов и 8 категорий, с вложенной XLSX. Эти верхние границы не гарантируют читаемости любого текста.
5. Выполните:

```bash
python3 scripts/run.py validate content/deck-spec.json
python3 scripts/run.py build content/deck-spec.json --backend portable --out result
```

`result` должен быть новым или пустым каталогом. Python 3.9+ достаточен для PPTX (`--no-render`). PDF/PNG требуют LibreOffice и Poppler. Оригинальные адаптеры используют portable; явный `--backend codex` отклоняется. Приоритет исполнения одинаков для Claude, Codex и Hermes.

## Файлы результата

- `content/deck-spec.json`, `content/assets/`, `content/sources.json` — переносимые входные данные.
- `output/presentation.pptx`, `output/scenario.md`; после рендера — PDF, PNG и контактные листы.
- `qa/structural.json`, `qa/visual-diversity.json`, `qa/run.json` — машинные результаты.

`notes` выводятся в сценарий, а `sources` — в отдельный журнал. В этой версии оригинального адаптера они **не записываются в заметки PowerPoint**, а адресуемость `source_ids` не проверяется автоматически. Для фактического отчёта вручную проверьте content-ledger и соответствие утверждений источникам. Проверки evidence_policy прежнего формата `/2` нельзя приписывать оригинальному контракту.

## Правила качества и ограничения

Создаваемый текст — Golos Text, заголовки SemiBold, цифры Bold. Оригинальные графические объекты и защищённые подписи сохраняются. Шрифты не встроены: установите файлы из `assets/fonts/` для редактирования.

Исходные layout/master/theme сохраняются без изменения байтов. Для редактируемого текста, принадлежащего layout (слайд 74), создаётся отдельная копия layout/master для каждого использования: изменение одной копии не затрагивает другую. Графики добавляются внутрь исходных пустых областей, с отступом под заголовки и показатели; это не восстановление отсутствующего в источнике стиля графика.

Растровые декоративные схемы сохраняются растровыми. Нельзя выдавать их за нативные связи. Если нужно изменять топологию, нужен отдельный адаптер; существующий native diagram из формата `/2` можно предложить как явно отличающуюся композицию, после проверки соответствия задаче.

Проверка длины и переноса предварительная. Не уменьшайте исходный шрифт ради переполнения. Сократите текст или разделите слайд. Три одинаковых семейства подряд дают предупреждение; обоснованная серия требует `repeat_reason` на каждом слайде серии. Разнообразие не важнее смысла.

`implemented` означает работающий адаптер полей с контрольным примером. Это не полная поддержка всех данных, экранов устройств, произвольных диаграмм или редактируемости декоративной графики. `tested` не присваивается автоматически после сборки. Структура, пиксельная регрессия пустого оригинала, просмотр заполненного примера и PowerPoint — разные проверки. Последний не проверен в текущем выпуске.

## Разработка

`original_template.py` заново инвентаризирует источник и сбрасывает статусы в candidate; после изменения источника нельзя сохранять старое доказательство поддержки. `original_schema.py` обновляет схемы по реестру. `run.py original-catalog` обновляет HTML/CSV, но не создаёт превью. Рендер и проверка новых примеров обязательны.

```bash
python3 -m unittest discover -s tests -v
# Для пиксельного теста нужны одинаково отрендеренные source-render и raw-render:
CGU_ORIGINAL_RENDER_ROOT=/path/to/render-fixtures python3 -m unittest discover -s tests -p test_original.py -v
```

Pillow требуется только для сравнения PNG. Тест меняет один пиксель и проверяет обнаружение регрессии. Совпадение пустых слайдов не заменяет проверку заполненного содержания. Тесты на границах вместимости и PowerPoint остаются отдельными задачами перед заявлением полной поддержки.
